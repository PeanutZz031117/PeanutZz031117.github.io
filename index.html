多态

1.1 多态的定义

​ 运⾏时多态，具体点就是去完成某个⾏为(函数)，可以传不同的对象就会完成不同的⾏为，就达到多种形态。

​ 多态条件：

  1. 父子类中有两个虚函数，并且他们的函数名，参数，返回值都相同就构成虚函数的重写
  2. 必须是父类的指针或者引用来调用虚函数

​ 以此实现虚函数：传父类调父类，传子类调子类。

​ 目的：实现了一些场景下很灵活的调用，根据调用对象的不同，来实现不同的函数。

​ 普通调用：看指针或者引用或者对象的类型

​ 多态调用：看指针或者引用指向的对象

​ 这里用A*指针指向B类，最后delete调用的是A的析构函数，这样会导致内存泄漏，因此引入了虚函数的第二种特殊情况。

​ 虚函数的两个特殊情况：

  1. 协变：虚函数的重写返回值可以不同，要求必须返回值是父子类关系的指针或者引用（父类不写virtual，则两个BuyTicket函数构成隐藏。子类不写virtual则两个虚函数仍然构成重写，因为重写是实现重写，他会把父类的声明拿下来，子类中的实现部分作为函数内容）
  2. 析构函数名字的特殊处理：在父子类的析构函数前面需要加上virtual（上面的子类不写virtual仍然满足多态构成重写关系，主要就是为了这部分服务，实现只在父函数部分写上virtual，后续子类就可以不写也构成重写，实现了析构函数的重写）

继承-cpp进阶

Posted on 2026-04-02 Edited on 2026-04-08

一、继承的概念及定义

1.1 继承的定义

​ 继承的本质是面向对象程序设计使代码复用的核心手段，可以保证在原有类（基类、父类）的基础（存放公共的信息）上进行扩展，形成派生类（子类）。

1.2 继承方式

​ 一共三种继承方式：public protected private，他们的区别如下图

​ 注意，这里的不可见不是不存在，只是无法访问父类的私有成员，但其实可以间接用，比如通过父类的成员函数例如getAge()。因此，如果希望成员可以使用父类的成员变量，则将其定义为protected。

​ 一般在实际应用中都是用public继承。

1.3 父类和子类的赋值兼容转换

​ 当前认为，只能子类赋值给父类，不能父类给子类。可以认为是一种切片，把子类的共有部分切片赋值给父类，并且与强制转换不同，这里没有中间变量（是一种特殊规则）。

1.4 父类和子类的作用域

​ 父类和子类分别是不同的作用域，他们可以有同名成员，此时，子类成员将会屏蔽父类对同名成员的直接访问，这种情况叫隐藏（成员函数只要函数名相同也构成隐藏，因此返回值和参数可以不相同）。在子类中访问的时候，优先访问子类的该成员，也可以通过作用域访问限定符来访问父类成员。

1.5 子类的默认成员函数

构造函数：

​ 默认构造函数：

​ 子类的成员:自定义类型和内置类型分别处理

​ 父类的成员：调用父类的构造函数

​ 自己写构造函数：

​ 对于父类的成员变量，需要在初始化列表调用父类的构造函数，并且永远都是先构造父类的变量（因为初始化列表初始化顺序本身就跟出现的顺序无关，只与声明的顺序有关）

​ 无论是构造初始化/拷贝/析构，都是多了父类的一部分

析构函数:

​ 子类的析构函数和父类的析构函数构成隐藏关系，因为由于多态的原因，析构函数会被特殊处理，都会处理成desructor()

​ 为了保证先子后父，因此父类的析构会在子类的析构后面自动调用（先父后子有安全隐患，因为子类的析构可能会访问父类的成员）

1.6 友元函数的继承问题

​ 友元函数不能继承，如果想友元，需要显示友元一下。

1.7 继承与静态成员

​ 基类定义了静态成员，则整个继承体系⾥⾯只有⼀个这样的成员。⽆论派⽣出多少个派⽣类，都只有⼀个static成员实例。（可以通过这个来统计该类直接或者派生出多少个）

1.8 多继承与菱形继承问题

单继承：⼀个派⽣类只有⼀个直接基类时称这个继承关系为单继承

多继承：⼀个派⽣类有两个或以上直接基类时称这个继承关系为多继承，多继承对象在内存中的模型是，先继承的基类在前⾯，后⾯继承的基类在后⾯，派⽣类成员在放到最后⾯。

有了多继承就可能出现菱形继承，这种情况下会出现数据冗余和二义性

1.9 虚继承

通过虚继承俩解决数据冗余和二义性，Virtual加在腰线上的位置，也就是student和teacher类的定义部分。也就是说把Person从student和teacher里都拿出来了，放到一个公共的位置。

基于采样的路径规划算法

采样规划算法简介

  1. PRM:1.先随机采样n个点构成图 2.基于图的搜索
  2. RRT:快速搜索随机树， 非最优解（连渐进最优都不是）。
  3. RRT*:找到解之后继续去做优化，知道达到给的最大搜索时间，因此时间慢。作了两个改进，一是改变了新节点连接到树的规则。二是对搜索树进行了剪枝操作，使其更接近于真实的最优路径。
  4. RRT-connect：双向扩展的RRT，从start和goal同时扩展，搜索速度比较快（对树的搜索要比对点的搜索更简单）。ROS-Moveit！默认使用此算法

RRT算法

RRT描述为：

  1. 采样（随机采样、）
  2. 寻找采样点距离最近的树节点
  3. 根据最大步长，把这个点控制在最大步长之内（相当于以根节点画一个圆，采样点在圆内就直接连接，不在则以连线与圆交点作为新的节点）
  4. 进行碰撞检测，如果未碰撞，则将新节点加入到树中

优点：

​ 能找到一条从start到goal的路径

***缺点(可以作为优化的点)***：

  1. 非最优解—>RRT*
  2. 算法效率低（时间长）—>RRT-connect
  3. 整个空间均匀采样

RRT*

RRT*描述为：

  1. 采样（随机采样等）
  2. 寻找采样点距离最近的树节点
  3. 根据最大步长，把这个点控制在最大步长之内（相当于以根节点画一个圆，采样点在圆内就直接连接，不在则以连线与圆交点作为新的节点）
  4. 进行碰撞检测
  5. （改进之处）如果未碰撞，则以xnew为圆心，r为半径，找圆中的节点（或找K-nearnest），在这K个点中重新选择父节点（要求为父节点到根节点的距离最短）
  6. （改进之处）对于剩下的K-1个节点进行重新连接

RRT-Connect

算法描述：

  1. 从start和goal分别生成一颗树
  2. 当两棵树连接时，生成路径
  3. 贪婪思想

算法优势：

  1. 增量式生长（分别生长）
  2. 搜索速度快

Informed-RRT*

改进：

  1. 在搜索空间上进行了处理
  2. 在第一次找到路径之后，缩小搜索空间来寻找更优解（也是存在缺点，可能在外面有更好的解）
